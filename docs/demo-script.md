# 窗间 · Windowfolk 演示脚本（v1「送花过桥」）

本文档用于录制比赛演示视频，也是 v1 的手动验收说明。按顺序操作可以从全新世界一次走完「许愿 → 架桥 → 桥塌掉落 → 梯子救援 → 种花 → 开花 → 回赠果子」的完整流程（Requirement 28.6）。

布局和每一步的几何关系与自动化场景测试 `Tests/WindowfolkCoreTests/DemoScenarioTests.swift` 一致。那个测试在 1440×900 的屏幕上用模拟窗口跑完同样的流程，`swift test` 通过就说明这套布局在逻辑上能走通。

## 1. 准备

### 1.1 构建应用

在仓库根目录运行：

```sh
./build-app.sh
```

脚本结束时输出 `完成：…/Windowfolk.app`，`Windowfolk.app` 生成在仓库根目录。

### 1.2 清空世界（每次录制前都要做）

演示必须从全新世界开始，也就是不存在 `world.json`。先退出正在运行的窗间（菜单栏图标 →「退出」），再删除存档：

```sh
rm -f ~/Library/Application\ Support/Windowfolk/world.json
```

不要在窗间运行时删除：退出时它会重新写入 `world.json`。

`events.jsonl` 不影响剧情，可以保留。想要一份干净的事件记录时一起删掉：

```sh
rm -f ~/Library/Application\ Support/Windowfolk/events.jsonl
```

### 1.3 整理桌面

- 只使用主显示器（带菜单栏的那块）。副显示器上的窗口不参与地形。
- 关闭或最小化其他所有应用窗口，主显示器上只留下演示用的两个窗口。家的分配取「水平中心距离最远的两个窗口」，多出来的窗口会抢走家的位置。
- 隐藏桌面图标（Finder 设置或 `defaults write com.apple.finder CreateDesktop false && killall Finder`，录完再改回 `true`），换一张纯色或简洁的壁纸。
- 关闭勿扰以外的通知，避免横幅挡住画面。
- Dock 保持显示（不要开自动隐藏）。Ground 是 Dock 上沿，Dock 隐藏后 Ground 会移到屏幕最底部，下面给出的高度都要跟着改。

## 2. 窗口布局

### 2.1 用哪两个窗口

用 2 个普通应用窗口，推荐两个 TextEdit 新建文稿窗口（`⌘N` 两次），或两个 Finder 窗口。要求：

- 两个窗口宽高都不小于 120pt（小于这个尺寸的窗口不算地形）。
- 不要全屏，也不要和其他窗口重叠。
- 窗口上沿就是居民走的路，标题栏上方不要有其他窗口遮挡。

### 2.2 位置和尺寸

以 1440×900 屏幕为例（Dock 在底部，Dock 上沿约在距屏幕顶部 825pt 处）。坐标都以屏幕左上角为原点，单位 pt：

| 窗口 | 角色 | 初始左边缘 x | 宽 × 高 | 上沿 y |
|---|---|---|---|---|
| 窗口 1（左） | 都都的家 | 约 100 | 约 300 × 150 | Dock 上沿往上约 175pt（1440×900 上约 650） |
| 窗口 2（右） | 嘟嘟的家 | 约 1000 | 约 300 × 150 | 与窗口 1 相同 |

1512×982 等其他屏幕按同样的规则摆：两个窗口一左一右相隔很远，上沿等高，都在 Dock 上沿往上约 175pt。

上沿高度是这个布局里最关键的数：

- 上沿离 Ground 要**超过 120pt**（Drop_Max_Height），这样窗沿和地面之间没有往下跳的通路，掉到地上的都都只能靠梯子回去。
- 上沿离 Ground 要**不超过 200pt**（Ladder_Length），这样梯子够得着。
- 取 160 到 190pt 之间都可以，175pt 两边都留了余量。
- 两个窗口上沿等高，这样木板是水平的，高差远小于 40pt 的限制。

摆窗口时可以打开菜单栏图标 →「显示路面」，蓝线是窗沿，棕线是地面。确认两个窗口上各有一条完整的蓝线后再关掉这个开关（开关打开时会一直画线，不适合录制）。

### 2.3 谁住哪个窗口

窗间启动时自动分配家：中心 x 较小（靠左）的窗口归**都都**（银渐层小猫），靠右的归**嘟嘟**（金丝熊）。两位居民出现在各自窗口最长那段窗沿的中点。

## 3. 演示流程

先摆好 2.2 的布局，再双击 `Windowfolk.app`（或在终端运行 `open Windowfolk.app`）。下面每一步写明玩家操作和应看到的画面。

### 步骤 1：都都许愿，无路可走

- **操作**：启动应用后什么都不做，等 2 到 3 秒。
- **画面**：菜单栏出现窗间图标，右下角 Dock 上方出现工具箱。都都抱着花盆站在左窗口上沿，头顶出现「花盆 + 嘟嘟头像」气泡，朝嘟嘟的方向张望不动。嘟嘟在右窗口上沿走走停停。
- **说明**：两窗口相距约 600pt，远超木板跨度 160pt，因此无路可走，剧情处于 `Waiting`。

### 步骤 2：拉近窗口，架起木板

- **操作 1**：拖动右窗口（嘟嘟的家）的标题栏，把它向左移到左边缘约 x = 500，上沿高度不变。此时两窗口之间留约 100pt 空隙。嘟嘟会跟着窗口一起移动。
- **操作 2**：在右下角工具箱的**左半边**（木板区）按下鼠标，拖到两个窗口之间的空隙上方、略高于窗沿的位置（约 x = 450）。
- **画面**：木板预览两端吸附到两个窗口相邻的窗沿端点上，预览为**绿色**。如果是红色，说明空隙太大（超过 160pt）或两个窗沿高差超过 40pt，把右窗口再往左挪一点。
- **操作 3**：在绿色时松开鼠标。
- **画面**：木板架好，都都立刻出发，抱着花盆（`carrying`，比空手走得慢）走向木板。

### 步骤 3：桥塌，都都悬挂后掉落

- **操作**：等都都走上木板（木板约 100pt 长，都都大约要 3 秒走过去），在它还在木板上时，迅速把右窗口向右拖开到左边缘约 x = 900。
- **画面**：两窗口间距超过 160pt 的那一刻木板失效并掉下去；都都停在原地挂在桥边约 1.5 秒（`hanging`），然后笔直掉到地面上，花盆一直抱在手里。
- **提示**：只要拖开超过 60pt 木板就会断，不必一次拖到 x = 900。没赶上（都都已经走到右窗口）时，退出、删除 `world.json`、从头再来。

### 步骤 4：地面张望，梯子救援，送到花

- **画面**：都都落地后在地面上找到离嘟嘟最近的位置，左右小范围来回走，抬头张望，头顶仍是「花盆 + 嘟嘟头像」气泡。
- **操作**：在工具箱的**右半边**（梯子区）按下鼠标，拖到右窗口（嘟嘟的家）上沿靠左的位置（约 x = 1000，即离窗口左边缘约 100pt），略高于窗沿。
- **画面**：梯子上端吸附到右窗口的窗沿上，下端竖直落到地面，预览为**绿色**。红色说明窗沿离地面超过 200pt，把右窗口往下挪一点。
- **操作**：在绿色时松开鼠标。
- **画面**：都都走到梯子下，爬上去（`climbing`），沿窗沿走到嘟嘟身边。

### 步骤 5：种花，快进开花

- **画面**：都都走到离嘟嘟 32pt 以内时，两人一起蹲下再跳一下（种花动画约 2 秒）。花盆留在嘟嘟所在的窗沿上，两人头顶出现心形气泡。
- **操作**：菜单栏图标 →「调试」→「快进」，花盆发芽；再选一次「快进」，花开。
- **说明**：不快进时，种下 90 秒后发芽，3 分钟后开花。

### 步骤 6：回赠果子，一起庆祝

- **画面**：花开的同时嘟嘟拿到一颗果子，走向都都（两人在同一条窗沿上，很快就到）。果子放在都都脚边的窗沿上，两人一起庆祝，然后回到闲逛。
- **说明**：这一轮到此结束。2 分钟后（或在「调试」中再选一次「快进」）开始第 2 轮，这次由嘟嘟送花给都都。

整段流程中只用到「快进」一项调试命令（Requirement 28.6）。

### 时间参考

| 环节 | 大约时长 |
|---|---|
| 启动到许愿气泡出现 | 1 到 3 秒 |
| 架桥后走到木板上 | 2 到 5 秒 |
| 悬挂 | 1.5 秒 |
| 掉到地面 | 不超过 2 秒 |
| 放梯子后爬上去送到 | 10 到 30 秒（取决于都都和梯子的距离） |
| 种花动画 | 2 秒 |
| 快进两次到回赠完成 | 5 到 15 秒 |

全程约 2 到 3 分钟。

## 4. 可选变体：切换桌面空间或最小化

用于验证 Requirement 28.8、28.9，也可以放进视频展示「最小化不掉东西」。在步骤 1 到 6 的任一阶段中途：

- **切换桌面空间**：用 `⌃→` 切到另一个桌面空间，在 60 秒内用 `⌃←` 切回。
- **最小化再恢复**：点黄色按钮最小化某个家窗口，在 60 秒内从 Dock 点回来。

期间：窗口看不见时，附着在上面的居民和物件一起消失，不掉落；窗口回来时它们出现在原来的位置（相对窗口左边缘的偏移差不超过 1pt），继续之前的动作。流程照常完成。

## 5. 录制建议

- 录制前按 1.2 清空世界，按 1.3 整理桌面，按 2.2 摆好窗口。
- 用 `⌘⇧5` 只录主显示器。录屏工具的控制条不要挡住窗沿和工具箱。
- 「显示路面」只用于摆窗口和排查问题，录制时保持关闭。
- 拖窗口时动作平稳一些，观众更容易看清居民随窗口移动。
- 步骤 3 是唯一需要抓时机的地方。可以先练一两遍，或者把都都走上木板到拖开窗口这段放慢解说。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 居民没有出现在窗口上，而是在地面上来回走 | 合格的窗口不到两个。检查两个窗口是否都在主显示器上、宽高都不小于 120pt、不是全屏。窗口够了之后会自动开局。 |
| 都都和嘟嘟住进了别的窗口 | 屏幕上还有其他窗口。退出窗间，关掉多余窗口，删除 `world.json` 后重开。 |
| 打开应用后剧情不是从头开始 | 上次的 `world.json` 还在。退出后按 1.2 删除。 |
| 木板预览一直是红色 | 两个窗沿之间的水平距离超过 160pt，或高差超过 40pt，或两端被别的窗口挡住。 |
| 梯子预览是红色 | 上沿离下方地面或窗沿超过 200pt。把窗口往下挪。 |
| 都都掉下来后没有张望，而是自己走回去了 | 窗沿离地面不超过 120pt，存在往下跳的路，或者窗口之间还有别的通路。按 2.2 抬高窗口。 |
| 整个世界突然消失 | 前台应用进入了全屏，或者有窗口铺满了整个主显示器。退出全屏后 1 秒内会恢复，世界状态不受影响。 |
| 窗口拖到副显示器后居民不见了 | 只支持主显示器。窗口中心移出主显示器后按「暂时看不见」处理，拖回来后居民和物件跟着回来。 |
| 点击空白处没有反应 | 正常现象：只有居民、物件、木板、梯子和工具箱能接收鼠标，其他位置的点击会落到下方应用。 |

## 7. 手动验收清单

以下条目依赖真实的窗口、屏幕和系统行为，无法用 `swift test` 自动验证。发布前逐项检查并勾选。

### 7.1 打包与启动

- [ ] **28.1** 在仓库根目录运行 `./build-app.sh`，不需要任何输入，以退出码 0 结束（`echo $?` 输出 `0`），生成 `Windowfolk.app`。
- [ ] **28.2** 人为制造一个失败（例如临时把 `Resources/Info.plist` 改名），再运行 `./build-app.sh`：退出码非零，终端输出「构建在步骤「…」失败」。检查完把文件改回。
- [ ] **28.3** 在 Finder 中双击 `Windowfolk.app`，5 秒内菜单栏出现图标，并出现透明覆盖层（工具箱可见）。

### 7.2 应用外壳与覆盖层

- [ ] **1.1** 运行时菜单栏有且只有 1 个窗间图标；Dock 中没有窗间图标；`⌘Tab` 切换器中没有窗间。
- [ ] **1.2** 覆盖层盖住整个主显示器，包括菜单栏和 Dock 区域（打开「显示路面」时地面棕线位于 Dock 上沿，工具箱在 Dock 正上方的右下角）。
- [ ] **1.3** 在没有居民、物件、工具箱和路面线的位置，桌面画面与退出窗间时一样：没有边框、标题栏、阴影或半透明底色。
- [ ] **1.4** 用 `⌃→` 切换到其他每个桌面空间，覆盖层（工具箱）都显示在普通应用窗口上方。
- [ ] **1.5** 在 TextEdit 中输入文字时点击工具箱或戳一下居民，TextEdit 仍是前台应用，继续输入的文字照常进入 TextEdit。
- [ ] **1.9** 选择菜单「退出」，进程在 2 秒内结束（活动监视器中消失）；`world.json` 的修改时间更新为退出时刻。
- [ ] **2.3** 在一个从未运行过窗间的用户账户（或用 `tccutil reset ScreenCapture` 和 `tccutil reset Accessibility` 重置权限后）首次启动，全程不弹出「屏幕录制」或「辅助功能」授权对话框，居民照常出现在窗沿上。

### 7.3 鼠标穿透

- [ ] **7.2** 在覆盖层的空白位置点击、拖动、滚动、右键，下方应用的反应与没有窗间时一样（例如能选中文字、拖动窗口、滚动网页、弹出右键菜单）。
- [ ] **7.3** 在居民、物件、木板、梯子或工具箱上点击和拖动，下方应用收不到这些事件（例如工具箱正下方的桌面图标不会被选中）。
- [ ] **7.4** 把指针静止放在嘟嘟闲逛的路径上，嘟嘟走过时指针下的点击被覆盖层接收，嘟嘟走开后约 0.1 秒内点击重新落到下方应用；指针快速移入移出工具箱时，切换没有可感知的延迟。

### 7.4 全屏、睡眠与显示变化

- [ ] **23.1** 让一个应用进入全屏（绿色按钮或 `⌃⌘F`），1 秒内居民、物件和工具箱全部消失。
- [ ] **23.2** 全屏期间，在原来工具箱和居民所在的位置点击，事件全部落到全屏应用。
- [ ] **23.3、23.4** 退出全屏（或 `⌘Tab` 切到非全屏应用），1 秒内居民、物件、木板、梯子和工具箱全部回来，数量和位置与全屏前一致。
- [ ] **23.5** 让 Mac 睡眠（苹果菜单 →「睡眠」）约 1 分钟后唤醒，2 秒内覆盖层和路面恢复正常（打开「显示路面」确认），居民仍在原窗口上。
- [ ] **23.6** 在「系统设置 → 显示器」中更改分辨率（或改变 Dock 大小、把 Dock 移到左侧再移回），2 秒内覆盖层盖满新屏幕，地面棕线和工具箱移到新的 Dock 上沿，地面上的居民和物件都在屏幕内。

### 7.6 性能与稳定性

- [ ] **29.1** 空闲 CPU 不超过 3%（单核百分比，Apple Silicon）。测量方法：
  - 打开「活动监视器」，选中 Windowfolk 进程，「显示」→「更新频率」设为每 1 秒。
  - 保持 29.1 定义的静止状态 60 秒：不动任何窗口、不拖拽、「显示路面」关闭、花不在这 60 秒内换阶段，所有居民处于 `idle` 或 `waiting` 且位置不变。
  - 记录这 60 秒内「% CPU」读数的平均值：______ %。
  - 注意：v1 的居民在 `idle` 时会走走停停（停 1 到 3 秒，走 1 到 4 秒），走动时轮询会回到 30Hz，因此严格满足 29.1 的静止状态很少出现。实际测量可以用步骤 1 的状态（都都在窗沿上等待不动），这时只有嘟嘟偶尔走动；这个读数不超过 3% 时，严格静止状态下一定也不超过。
- [ ] **29.3** 连续运行 2 小时不崩溃、不被系统终止。期间至少完成：
  - [ ] 移动窗口 20 次
  - [ ] 关闭窗口 5 次（关闭时上面的居民和物件掉下来）
  - [ ] 最小化并恢复窗口 5 次
  - [ ] 切换桌面空间 2 次
  - [ ] 完成 1 个 Story_Round（回赠果子并庆祝）
- [ ] **29.4** 2 小时运行结束时，点击菜单栏图标 1 秒内弹出菜单；拖动某位居民所在的窗口，1 秒内居民跟着移动。
