# 窗间 · Windowfolk 素材规格（v1）

本文档写明替换占位图形所需的全部 PNG 素材。按规格把 PNG 放进素材目录，重启应用后对应的占位图形就会被替换，显示尺寸和位置不变。不合格或缺失的文件只让那一项继续使用占位图形，应用不会弹出任何提示。

素材清单的唯一来源是代码中的 `Sources/WindowfolkCore/AssetCatalog.swift`。本文档与它保持一致；两者不一致时以代码为准，并修正本文档。

## 1. 角色设定

### 都都（Resident_A）

- **形象**：圆脸银渐层小猫。毛色是银白到浅灰的渐层，背部和头顶颜色略深，四肢和肚子偏白。
- **特征**：圆脸、短鼻子、三角形小耳朵（耳内粉色），眼睛大而圆，翠绿或蓝绿色。尾巴蓬松，尖端略深。
- **性格**：好奇、有点急性子、热心。想到要送东西就停不下来，没路时会踮脚张望，摔下来也很快爬起来。
- **动作气质**：步子小而快，常常歪头；开心时尾巴竖起来。

### 嘟嘟（Resident_B）

- **形象**：金丝熊（金黄色仓鼠）。毛色金黄偏橘，肚子和嘴边是奶白色。
- **特征**：圆滚滚的身体、圆形小耳朵、黑亮的小眼睛、鼓鼓的腮帮，前爪小小的，常常捧在胸前。几乎看不到尾巴。
- **性格**：慢悠悠、温和、知足，喜欢收集东西。收到礼物会认真地回赠。
- **动作气质**：走路左右晃，动作比都都慢半拍；开心时原地蹦一下，腮帮更鼓。

两位都是 Q 版比例：头身比约 1:1，头部占身体大部分，四肢很短。整体风格参考 QQ 宠物和早期桌面小精灵：轮廓清楚、配色柔和、在 32pt 的小尺寸下依然能一眼认出。

## 2. 素材目录

应用启动时、Overlay 首次渲染之前，按以下顺序查找素材目录，**只使用第一个存在的目录**：

1. 环境变量 `WINDOWFOLK_ASSETS` 指定的目录（支持 `~`），例如 `WINDOWFOLK_ASSETS=~/Desktop/windowfolk-art swift run Windowfolk`。用于美术调试，不必重新打包。
2. `Windowfolk.app/Contents/Resources/Assets/`。打包脚本 `build-app.sh` 会把仓库根目录的 `Assets/` 复制到这里。
3. 当前工作目录下的 `Assets/`，也就是在仓库根目录 `swift run` 时的 `<仓库根目录>/Assets/`。

三个目录都不存在，或目录里没有符合命名规则的 PNG 时，全部使用占位图形，应用正常启动。

素材只在启动时读取一次。替换 PNG 后需要退出并重新打开应用。

## 3. 通用规则

- **格式**：PNG（文件内容必须是 PNG，不能把 JPEG 改扩展名），8 位 RGBA。
- **透明背景**：背景必须完全透明（alpha = 0），不要留白底、棋盘格或阴影底板。角色边缘可以有半透明抗锯齿，但不要有残留的白边或彩边。
- **命名规则**：文件名 = 素材键 + `.png`，全部小写，单词之间用下划线，**区分大小写**，必须与第 5 节表格完全一致。不在表中的文件会被忽略。
- **分辨率**：所有尺寸以 pt 计，PNG 按 **@2x** 提供，即像素尺寸 = pt 尺寸 × 2。例如 32×32pt 的一帧对应 64×64 像素。
- **sprite sheet**：多帧素材把所有帧放在一张图里，**从左到右水平排列**，帧与帧之间没有间隔、没有边框。整张图宽度 = 每帧像素宽 × 帧数，高度 = 每帧像素高。单帧素材就是一张单帧图。
- **校验**：应用逐项检查文件名、能否解码、像素高度是否等于每帧像素高、像素宽度是否等于每帧像素宽 × 帧数。任一项不符时只有这一项回退为占位图形。PNG 中的 DPI 元数据不影响校验，只看真实像素数。
- **锚点**：居民、花、果子和气泡都以**每帧底边中点**为锚点，对齐到所站的路面（或头顶气泡的位置）。角色的脚底要贴住每帧的底边（底部最多留 1 到 2 像素），并在水平方向居中，否则会看起来浮空或偏移。
- **朝向**：居民一律画成**朝右**。朝左时应用会水平镜像，所以不要画左右不对称的文字或标记。
- **播放速度**：循环动画按 8 帧/秒播放（桌面静止时降到 2 帧/秒）。`planting` 和 `celebrating` 按进度从第一帧播到最后一帧，不循环。

## 4. 各状态的动画内容

两位居民的每个 Resident_State 各一张 sprite sheet，帧数如下（两位相同）：

| 状态 | 帧数 | 动画内容 | 循环 |
|---|---|---|---|
| `idle` | 4 | 站着呼吸，身体轻微起伏，偶尔眨眼 | 是 |
| `walking` | 6 | 空手走路，一个完整步伐周期 | 是 |
| `carrying` | 6 | 双手抱着东西走路，比 walking 更稳更慢；**不要画出物件本身**，物件由应用另外叠加在胸前 | 是 |
| `waiting` | 4 | 原地抬头张望，左右看 | 是 |
| `falling` | 2 | 下落中，双手举起、眼睛睁大 | 是 |
| `hanging` | 2 | 双手向上抓住桥边，身体悬空轻晃 | 是 |

## 6. 用 gpt-image-2.5 生成时保持角色一致

图像模型每次生成都会有差异，下面的做法能让 29 张图看起来属于同一套美术。

### 6.1 先做角色设定图

1. 为都都和嘟嘟各生成一张**角色设定图**（character sheet）：同一张图里画正面、侧面（朝右）、背面三视图，外加一行颜色色块。满意后固定下来，后续每次生成都把它作为参考图上传。
2. 从设定图里取出 4 到 6 个固定颜色（主色、阴影色、高光色、描边色、腮红色），记成十六进制色值写进提示词，例如「主色 #C8CCD4，描边 #6E7380」。
3. 两位角色放在同一张图里生成一次合影，确认体型比例协调（都都略高，嘟嘟更圆）。

### 6.2 固定提示词前缀

所有图都使用同一段前缀，只替换后面的动作描述。示例：

```text
Cute chibi pixel-friendly sprite for a macOS desktop pet game, soft pastel palette,
clean 2px dark outline, flat shading with one shadow tone, transparent background,
character faces right, feet touching the bottom edge, centered horizontally,
no text, no ground shadow, no background. Character: [都都 / 嘟嘟 的设定描述].
Use the attached character sheet as the exact design reference.
```

动作部分写清楚帧数和排列，例如：`A horizontal sprite sheet of 6 equal frames, left to right, showing a walk cycle.`

### 6.3 一个状态的所有帧在同一张图里生成

- 不要一帧一帧单独生成，否则每帧的脸和比例都会不同。一次生成整条 sprite sheet，模型会在同一张图里保持一致。
- 让模型生成**比目标大的画布**（例如每帧 256×256 像素），帧数和排列与规格一致，之后再缩小到 64×64。
- 生成后检查：每帧的头顶高度、脚底位置是否一致；走路周期首尾两帧能否衔接。

### 6.4 去背景

- 即使提示词写了透明背景，模型也可能输出白底或假的棋盘格。生成时优先选择透明背景输出选项；没有时，用纯色背景（例如 #00FF00 绿幕）生成，再用抠图工具去掉。
- 去背景后放到深色和浅色背景上各检查一次，确认没有白边、绿边或残留的阴影。

### 6.5 缩放与像素对齐

1. 把整条 sprite sheet 按帧切开，每帧单独对齐：脚底贴住底边，水平居中。
2. 每帧缩放到 64×64 像素（@2x），使用高质量缩放（Lanczos 或双三次），不要用最近邻放大小图。
3. 重新按从左到右的顺序拼回一张图，帧之间不留间隔。整张图的像素尺寸必须与第 5 节表格完全一致。
4. 描边粗细在 64×64 下保持 2 像素左右，太细在屏幕上会糊掉。

### 6.6 调色板一致

- 所有素材共用一套调色板：木制物件（木板、梯子、工具箱、花盆）用同一组木色；植物用同一组绿色。
- 生成完一批后，可以在图像编辑器里把相近颜色统一替换为调色板中的色值，避免不同图之间颜色漂移。

## 7. 交付检查清单

放进素材目录之前逐项确认：

- [ ] 文件名与第 5 节表格完全一致（小写、下划线、`.png`）。
- [ ] 文件确实是 PNG，带透明通道，背景完全透明，没有白边或棋盘格。
- [ ] 整张图的像素尺寸与表格一致（@2x，宽 = 每帧宽 × 帧数）。
- [ ] 多帧素材从左到右水平排列，帧之间没有间隔或边框。
- [ ] 居民朝右，脚底贴住每帧底边，水平居中；所有帧的头顶高度和脚底位置一致。
- [ ] `carrying` 不画物件，`climbing` 不画梯子。
- [ ] 三张花的图用同一个花盆，位置一致。
- [ ] `plank.png` 左右可无缝拼接，`ladder.png` 上下可无缝拼接。
- [ ] `toolbox.png` 左半边是木板、右半边是梯子。
- [ ] 气泡里没有文字字符；`bubble_wish.png` 右半边留给头像。
- [ ] 都都和嘟嘟的配色、比例与角色设定图一致。
- [ ] 放入素材目录并重启应用后，在深色和浅色桌面背景下都检查过显示效果；仍显示占位图形的那一项，说明文件名或像素尺寸不符，按本清单重新检查。
