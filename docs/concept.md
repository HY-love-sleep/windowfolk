# 窗间 Windowfolk

## 项目创意说明

> 你的窗口，是它们的世界。
>
> A little civilization between your windows.

**命名说明：**“窗间”指窗口之间，也是居民生活的缝隙；Windowfolk 意为住在窗口世界里的小居民。中英文名目前为项目工作名，尚未进行商标、域名或应用商店名称冲突检查。

---

## 一、作品是什么

**窗间 Windowfolk 是一款把电脑窗口布局转化为可交互地形的桌面微型世界。**

小居民生活在应用窗口的边缘。窗口上沿是道路，窗口之间的空隙是峡谷，用户放下的桥梁和梯子是交通设施。你不直接操纵每个居民，而是通过移动窗口、连接道路和放置少量物件，让它们能够搬运、拜访、布置住所，完成一件件小事。

它继承早期桌面宠物与 Flash 小游戏的亲切感，但不止于“有角色在屏幕上走动”。它的核心是：**你改变桌面的空间关系，居民的生活就跟着改变，并留下可见的结果。**

这不是给 AI 助手套上角色形象，也不是模拟经营面板。它是一个可以动手摆弄、观察反应、逐渐建立感情的桌面玩具。

## 二、希望创造的感受

许多人的电脑桌面只有工作窗口、通知和任务。窗间希望在这些熟悉的矩形之间，放进一点不以效率为目的的生命感。

你移动一个窗口，不只是整理工作区，也可能缩短两个小家的距离。你架起一块木板，不是完成生产指标，而是让一个抱着花盆的小家伙终于能去拜访邻居。

作品不靠不停弹出提示吸引注意。理想体验是：你正常使用电脑，偶尔注意到窗沿上的居民；想玩时，可以介入几分钟，不想玩时，可以安静地放着、隐藏或退出。

**核心情绪是好奇、亲切，以及“我让一件小事发生了”的满足感。**

## 三、一个完整的代表场景

屏幕上有两个窗口。左边的窗沿住着一个抱花盆的小居民，右边的窗沿有另一个居民和一块空花床。

左边的居民走到窗口边，发现距离太远，停下来望向对面。它不是弹出任务列表，而是看向花盆、再看向邻居，用动作表达想去的地方。

你把两个窗口拉近，进入布置模式，在两侧窗沿之间放下一块木板。系统确认桥梁可连接后，居民抱着花盆走过桥。对面的居民接住花盆，两人把花种在窗沿。

花留在那里，成为这个小世界的新变化。

随后你把窗口拉开。桥梁不再有效，角色先停止进入危险路段，再执行预先设计的回退或安全安置动作；居民不会穿过空气，或永远悬在原地。如何表现“收桥”和“重新找路”，需要结合原型验证，不能预先假定任何动态变化都能无缝处理。

**这段体验完整表达了作品：改变布局 → 连接通路 → 居民行动 → 世界留下变化。**

## 四、核心玩法循环

### 1. 看见一个小愿望

居民有具体、可观察的小目标，例如把花送给邻居、把一本书送到阅读角、把靠垫搬回小窝。第一版使用手工设计的目标，不依赖无限生成任务。

### 2. 改变空间

用户移动、缩放窗口，或在可连接的位置放置桥梁。前期只围绕横向连接和有限高度差设计，不承诺任意角度、任意距离的万能搭建。

### 3. 看居民把事情做成

居民依据当前地形和行为规则寻路、搬运、等待和互动。路径中断时有清楚的反馈，而不是偷偷传送完成目标。

### 4. 留下一个结果

一盆花、一处阅读角、一面小旗，或一段新的邻里关系，让成功不仅体现为数字加一。

### 5. 再试一种布局

改变窗口关系，尝试另一条通路或另一件小事。作品靠空间组合与角色反馈产生重玩价值，不靠签到和强制倒计时拖长体验。

## 五、用户如何操作

### 陪伴模式

居民以低频、克制的方式活动。默认不抢键盘焦点，不随意弹出声音或通知；不操作系统中的真实文件，也不替用户点击其他应用。

### 布置模式

用户主动进入编辑状态，查看可站立边缘与连接点，放置、移动或移除设施。编辑状态与正常工作状态应明显区分，避免桌面上的透明覆盖层阻挡日常操作。

### 随时退出

提供隐藏、暂停、静音、重置场景和退出入口。全屏应用中的表现、是否自动隐藏，需要通过目标系统实测决定。

## 六、小居民的设计

居民不是带聊天框的通用助手，而是能通过动作表达意图的小角色。

第一版可以让两个居民拥有不同的行为倾向，例如一个愿意尝试新路，另一个更喜欢留在固定角落。差异应体现在等待、探索和使用物件的方式，而不只是名字或颜色。

角色需要能清楚表达几种状态：发现目标、准备行动、搬运、受阻、等待、完成和休息。美术风格优先考虑轮廓清楚、动作易读、能持续制作的原创二维角色。

幽灵或小精灵可以作为万圣节主题角色候选，但不提前锁定。若采用幽灵设定，应解释它们为什么仍遵守通路规则，例如它们搬运的实体物件需要桥梁；不能一边强调随意漂浮，一边要求用户修桥。

## 七、与现有桌宠的区别

已有开源项目实现了窗口检测、窗口边缘行走、重力、拖拽，以及多宠物互动。这些能力不是窗间的原创点。

窗间的设计重点是把已有技术进一步组织为玩法：

| 常见窗口感知桌宠 | 窗间的目标 |
| --- | --- |
| 窗口决定宠物站在哪里 | 窗口布局决定哪些生活行为能够发生 |
| 主要通过点击角色互动 | 主要通过改变空间与连接设施互动 |
| 动作结束后恢复待机 | 行动完成后留下物件或场景变化 |
| 单个角色的表现为中心 | 居民、物件和通路之间的关系为中心 |

这是一项待验证的产品差异，而不是已经证明的市场空白。后续仍需继续对照同类玩法，避免把现成能力当作创新。

## 八、技术形态与边界

### 产品形态

目标是本地桌面客户端，优先验证用户日常使用的 macOS。VPS 不是必要条件，首版不为使用服务器而增加账号、云同步或在线后台。

### 基本结构

1. **窗口感知层：**获取允许读取的窗口几何信息，处理显示器坐标、遮挡与窗口变化。
2. **地形层：**把可使用边缘抽象成平台，把桥梁等设施抽象成连接关系。
3. **行为层：**用状态机或行为树执行目标，结合路径图决定移动与搬运。
4. **表现层：**绘制透明覆盖层、角色动画、物件和反馈，区分编辑与鼠标穿透状态。
5. **保存层：**保存居民、物件和进度；重启后按规则恢复，不假定系统窗口标识永久稳定。

核心行为不需要 LLM。代码框架暂不锁定，应比较原生 macOS 与跨平台外壳的实际成本后再选。

### 隐私原则

首版只争取必要的窗口几何信息，不默认读取窗口内容、标题、屏幕截图或键盘输入。具体系统 API 与权限要求必须实测，不能预先承诺完全不需要权限。

### 技术难点

- 被前方窗口遮挡的平台不应仍被当作完整可行走道路。
- 窗口移动、缩放、最小化或关闭后，路径和附着设施需要安全失效。
- 桥梁上的居民遇到路径变化，需要明确的安全规则。
- 多屏、缩放、系统桌面空间与全屏行为可能存在平台差异。
- 覆盖层不能抢焦点或大面积挡住鼠标。
- 角色行为和绘制应控制 CPU、内存与电量开销。

这些是原型验收重点，不是已解决的能力声明。

## 九、最小可验证作品

首个可玩版本只证明一个闭环：

**两个居民，两个平台，一座桥，一次花盆搬运，以及搬运后仍保留的花。**

必要能力：
- 看得懂的居民状态与基础动画。
- 平台与通路的计算。
- 用户主动连接和移除桥梁。
- 路通则行动，路断则停止或安全回退。
- 目标完成后的可见结果和保存恢复。
- 正常操作其他窗口时不抢焦点、不大面积挡鼠标。
- 隐藏、暂停与退出。

若真实窗口感知带来较多不确定性，可先用可控的模拟窗口验证玩法，再进入真实桌面。但模拟窗口原型不等于真实桌面版本完成，不能混淆两者的验收结果。

## 十、第一版明确不做什么

- 不做通用 AI 助手、聊天或编码 Agent 状态监控。
- 不做无限居民、复杂经济、繁殖和完整城镇经营。
- 不同时承诺 Windows、macOS、Linux 全平台适配。
- 不默认读取屏幕内容或操作真实文件。
- 不做任意物理沙盒和无限自由搭建。
- 不加入签到、在线时长奖励或离开惩罚。
- 不以接入 LLM 作为创新卖点。

## 十一、参赛表达

### 建议主题方向

优先考虑 **Resurrection**：复活早期桌面宠物与互动桌面，但把原本作为背景的应用窗口，重新解释为有空间关系、可改变的生活环境。

这是对主题契合度的设计判断，不代表主办方已确认资格。正式提交前需再次核对本届规则及最终作品形态。

### 开发工具与成品的关系

Kiro 用于实际开发、规格推演、实现、测试与问题修复，保留有实质内容的 `.kiro` 记录。成品不要求运行时接入 Kiro，也不要求使用模型 API。

### 开源复用原则

可研究 DesktopPetMac 等项目的窗口感知、动画与桌面集成方式，但采用前应核实代码质量、许可证与素材权利。披露既有代码和依赖，清楚区分比赛期间新增的工作。不能简单换角色或界面便宣称完成了新的玩法。

### 建议展示主线

1. 普通桌面上出现两个小居民，观众立即理解它们住在窗沿。
2. 一只居民抱花盆，因窗口距离而无法前进。
3. 用户移动窗口、放桥，居民完成拜访与种花。
4. 用户改变布局，展示断路后的安全反馈。
5. 展示保存恢复，以及正常工作时的低干扰状态。

桌面客户端如何满足比赛要求的可运行应用 URL 与评委测试流程，需要正式确认。下载页、安装包与网页演示是候选交付方式，不能预先认定仅有下载链接便必然满足要求。

## 十二、作品成立的判断标准

- 用户无需长篇说明，就能理解“窗口是地形”。
- 用户改变布局，会引起明确、有因果关系的行为变化。
- 看完第一次花盆搬运，用户想再试一种连接方式。
- 居民不是随机走动的装饰，完成的事情留下可感知结果。
- 用户愿意把它留在自己的电脑上，而不只愿意看一段展示视频。
- 常驻带来的干扰与资源消耗在真实测试中可以接受。

**如果窗间只实现了小人在窗口上行走，它还只是一个技术演示；如果用户开始主动移动窗口，想帮这些小家伙把一件事情做成，它才成为一个作品。**
